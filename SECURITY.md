# Модель доступа и безопасность

## Что защищается

Каждый API-запрос из мини-приложения проверяет Telegram HMAC и `auth_date` (не более часа, с допуском 30 секунд в будущее). Запросы с сайта несут ключ входа (см. «Вход на сайте»). Клиент не передаёт доверенный user ID. Переданные поля `owner_id`/`user_id` не участвуют в выборе владельца подарка. Нет dev-пароля или серверного демо-режима.

Свои желания доступны владельцу; чужие — только подтверждённым друзьям или по активной гостевой ссылке на конкретного владельца. Дружба возникает либо после того, как получатель принял заявку по нику, либо когда человек открыл ссылку-приглашение и подтвердил дружбу. Создав ссылку, автор уже согласился. Ник берётся только из подписанных данных Telegram; если ник перешёл к другому аккаунту, он закрепляется за последним вошедшим владельцем. Ожидающая заявка доступа не даёт. Архивные желания видит только владелец. Фотографии защищены теми же правилами. Изменение/удаление подарка — только владельцем. При бронировании доступ проверяется повторно в атомарной SQL-команде. Все параметры SQL связаны через `bind`.

## Секретные брони

Для владельца в основном вишлисте SQL-запрос списка не обращается к `reservations`. Сериализатор не добавляет полей статуса, личности дарителя, времени или счётчика. Сортировка не зависит от брони. Редактирование и удаление собственного подарка имеет одинаковый результат с бронью и без неё. Владелец не может вызывать операции над собственной бронью; они отклоняются до обращения к таблице броней.

Другой авторизованный читатель видит только `available`, `reserved` или `mine`. Публичные списки не возвращают имя и Telegram ID зарегистрированного дарителя. Свою бронь можно отменить после отзыва доступа или удаления из друзей. Архивные желания нельзя забронировать.

Гостевая ссылка намеренно показывает статусы всех подарков даже владельцу, открывшему её. При копировании открывается предупреждение о раскрытии сюрприза. Для гостевой брони нужно имя покупателя; это неподтверждённое имя, не Telegram-идентичность. Ни публичный список, ни владелец это имя не видят. Отменить гостевую бронь можно только кодом отмены: его получает браузер гостя при бронировании, а в базе хранится только SHA-256 кода. Все типы броней используют общий уникальный слот `gift_id`, поэтому двойное бронирование исключено.

**Граница гарантии:** основной вишлист скрывает обычные брони; гостевая ссылка раскрывает статусы по явному выбору владельца. Администратор Cloudflare с доступом к базе может видеть брони.

## Перенос в архив

Основной список по-прежнему не содержит статуса брони. Перенос в архив принимает любую причину, ответ не зависит от наличия брони и не раскрывает дарителя. Эндпоинты `archive-status` и `archive-donor` удалены, новые архивные записи не сохраняют имя дарителя, а API архива не возвращает старые поля `gifted_by_*`.

### Совместные подарки

Организатор (владелец записи в `reservations`) приглашает своих подтверждённых друзей. Дружба проверяется в SQL-вставке, владельца вишлиста пригласить нельзя: это запрещает триггер `no_owner_member`. Участники хранятся в `reservation_members`. Ни один запрос, доступный владельцу, эту таблицу не читает. Приглашённый видит название подарка, даже если не дружит с владельцем, но не видит остальных приглашённых. Остальные читатели видят такой подарок просто как `reserved`.

### Бот и уведомления

Webhook `/api/telegram/webhook` принимает обновления только с заголовком `X-Telegram-Bot-Api-Secret-Token`, равным SHA-256 от `webhook:<BOT_TOKEN>`, поэтому отдельный секрет не нужен. Личность пользователя в боте берётся из поля `from` проверенного обновления. Изменять через бот можно только свои желания: каждый запрос содержит `owner_id`. Уведомления отправляются после ответа API (`waitUntil`), ошибка Telegram не влияет на запрос. Получатели событий о бронях — только дарители. Владелец вишлиста никогда не получает сообщений о бронях своих подарков. Подписчик получает новости, только пока он друг владельца. При удалении из друзей подписки в обе стороны удаляются. Если Telegram ответил 403, бот перестаёт писать человеку, пока тот снова не напишет боту.

## Постоянные ссылки на вишлист

Два независимых секрета по 32 случайных байта, base64url: `startapp=s_…` требует Telegram-входа, `#guest=…` открывает гостевой просмотр и бронирование без регистрации. Обе ссылки ограничены одним владельцем и не истекают автоматически (техническая дата — конец 9999 года). Повторное открытие окна возвращает те же ссылки для пары «владелец — создатель»; отзыв одной ссылки не отменяет брони и не отзывает вторую.

В D1 хранится SHA-256 для проверки и исходный секрет в `token_value`, чтобы владелец мог снова скопировать ту же ссылку. API возвращает секреты только владельцу после авторизации; публичные ответы их не содержат. Доступ к базе означает доступ к этим ссылкам. Старые действующие ссылки становятся постоянными; отозванные и уже истёкшие не восстанавливаются.

API получает секрет в `X-Guest-Token`. Не добавляйте аналитику, error tracking, service worker cache, access logs или сторонние виджеты, которые собирают URL или заголовки. Передавайте ссылки только адресатам списка.

## Профиль, актуальность и пересылка

Дата рождения хранится как день и месяц (`MM-DD`), без года и возраста. Она возвращается вместе с профилем только читателям, которые уже имеют доступ к вишлисту. Обратный отсчёт считает календарные дни в часовом поясе читателя; для 29 февраля в невисокосный год используется 28 февраля.

`wishlist_updated_at` обновляют триггеры базы при добавлении, изменении и удалении желания, включая импорт, архивирование и восстановление. При миграции дата восстанавливается по имеющимся подаркам. Брони и входы не меняют её, чтобы активность дарителей не раскрывалась владельцу. Пустой список без известной истории изменений имеет `NULL`.

Владелец по умолчанию разрешает пересылку. Авторизованный читатель с действующим доступом может создать собственную пару ссылок на чужой вишлист; они ограничены тем же владельцем и привязаны к создавшему их пользователю (`created_by`). API никогда не возвращает ему секреты ссылок владельца или других читателей.

Запрет в профиле блокирует выдачу чужих ссылок и отзывает все ссылки, созданные читателями. Разрешение после запрета не восстанавливает отозванные ссылки. Права повторно проверяются в SQL при выдаче ссылки и бронировании, а также при чтении по ссылке. Ссылки, созданные самим владельцем, продолжают работать, пока он их не отзовёт. Ручную пересылку уже известного URL технически запретить нельзя; настройка управляет выдаваемыми приложением ссылками.

## Фото профиля

- Фото хранится в `users.photo` как сжатый data URL (JPEG, PNG или WebP, не больше 120 000 символов). Сервер сверяет объявленный тип с первыми байтами файла; SVG и ссылки не принимаются.
- `GET /api/users/:id/photo` отдаёт фото самому человеку, его друзьям и тем, кому он прислал или от кого получил заявку, участникам общих праздников и тем, у кого есть действующая ссылка на его вишлист (та же проверка `canView`, что у списка). Остальным — 404. В профилях и списке друзей приходит только `photo_at` (версия для кэша), без самого фото.
- Фото из Telegram скачивает сервер: через Bot API (`getUserProfilePhotos` и `getFile`) или, если бот его не видит, по `photo_url` из подписанных `initData` / claim `picture` из `id_token`. Ссылки принимаются только с доменов Telegram (`t.me`, `telesco.pe`, `telegram.org`) и загружаются общим защищённым загрузчиком с ограничением размера. URL с токеном бота браузеру не отдаётся.
- Автоматически фото берётся один раз (`photo_checked`), после ответа на запрос, и только если у человека ещё нет своего фото. Дальше оно меняется только по просьбе человека.

## Вход на сайте

Кнопка «Войти через Telegram» использует новый вход Telegram по OpenID Connect. Сайт сам открывает окно `oauth.telegram.org/auth` с теми же параметрами, что и официальная библиотека `telegram-login.js` (`response_type=post_message`), поэтому сторонний скрипт на страницу не загружается. Параметры `origin` и `bot_id` не передаются: с ними Telegram открывает старый Login Widget, ответ которого сервер не принимает. Окно позволяет выбрать аккаунт, подтвердить вход и возвращает подписанный `id_token` через `postMessage`; сайт принимает сообщение только от `https://oauth.telegram.org` и только из открытого им окна. Старый виджет входа (`/api/auth/telegram-login`) удалён.

- Перед входом сайт получает от `POST /api/auth/nonce` случайный nonce (32 байта, base64url). В D1 (`login_nonces`) хранится только его SHA-256, срок 10 минут, при входе nonce удаляется — один `id_token` нельзя использовать дважды. Лимит: 30 nonce в минуту с одного IP.
- `POST /api/auth/telegram-oidc` проверяет `id_token` (`worker/oidc.ts`): подпись открытым ключом Telegram из `https://oauth.telegram.org/.well-known/jwks.json` (только RS256 и ES256; `none`, HMAC и прочие алгоритмы отклоняются), `iss = https://oauth.telegram.org`, `aud` = ID бота, `exp`, `iat` не старше 10 минут, наш nonce. Ключи кэшируются на час; неизвестный `kid` перезагружает их не чаще раза в минуту. Запрос ключей идёт через общий защищённый загрузчик только на `oauth.telegram.org`.
- Аккаунт определяется по claim `id` (Telegram user ID, приходит со scope `profile`), а не по `sub`, поэтому вход с сайта попадает в тот же аккаунт, что и мини-приложение. Токен без `id` отклоняется. Данные мини-приложения (`initData`) не принимаются как `id_token` и наоборот.
- После проверки сервер выдаёт 32 случайных байта (base64url) на 30 дней. В D1 хранится только SHA-256, не больше 10 входов на аккаунт (старые удаляются), просроченные чистятся по расписанию. Имя и ник для входа с сайта берутся из базы и обновляются только подписанными данными Telegram.
- Сайт хранит ключ в `localStorage` и отправляет в `Authorization: Session …`. Cookies не подходят: API на другом домене (`workers.dev`), и браузеры блокируют сторонние cookies. Защита от кражи ключа — отсутствие стороннего JavaScript, кроме скриптов Telegram, строгая CSP и экранирование React. Не добавляйте аналитику и чужие скрипты на сайт.
- «Выйти» удаляет текущий ключ на сервере, «Выйти на всех устройствах» — все ключи аккаунта (доступно и из мини-приложения). Отозванный или просроченный ключ сайт забывает сам и показывает кнопку входа.
- `GET /api/auth/config` отдаёт ID бота (первую часть токена) — это публичная информация, токен не раскрывается.
- Лимит: 10 попыток входа в минуту с одного IP.

## Ссылки-приглашения в друзья

Отдельны от постоянных ссылок на вишлист: 32 случайных байта, в D1 только SHA-256, срок 30 дней, новая ссылка отзывает прежние, отзыв в любой момент. Токен передаётся в `startapp=f_…` и попадает в API только в теле POST-запроса. Тот, у кого есть ссылка, может стать другом автора: отправляйте её только тем, кого хотите видеть в друзьях.

## Загрузка данных с других сайтов

Сервер скачивает страницы и файлы по ссылкам только по запросу вошедшего пользователя: при подтягивании цены и фото, загрузке картинки по ссылке и импорте Google Таблицы. Правила в `worker/net.ts`:

- Только `https`, порт 443, без логина и пароля в URL. IP-адреса (в том числе в десятичной и шестнадцатеричной записи), IPv6-литералы, `localhost`, имена без точки и внутренние зоны (`.local`, `.internal`, `.lan`, `.home.arpa` и т. п.), а также `*.workers.dev` отклоняются. Workers не имеет доступа к частным сетям, но правило защищает и локальную разработку через `wrangler dev`.
- Редиректы следуют вручную (не больше 5), каждый адрес проверяется заново. Импорт таблиц допускает только `docs.google.com` и `*.googleusercontent.com`.
- Таймауты: 8 с на страницу, 12 с на весь разбор ссылки, 10 с на картинку, 25 с на таблицу. Размер: HTML обрезается до 2 МБ, картинка — не больше 12 МБ, таблица — не больше 40 МБ.
- Картинка определяется по сигнатуре байтов (JPEG, PNG, GIF, WebP, AVIF, HEIC). SVG и всё остальное отклоняется. Ответ с картинкой или таблицей отдаётся с `Content-Disposition: attachment` и `Content-Security-Policy: sandbox`, поэтому origin API не может отрисовать его как страницу. Браузер затем перекодирует картинку в WebP и сохраняет только её.
- HTML не исполняется и не отображается: из него регулярными выражениями извлекаются строки (название, цена, адрес картинки). Название очищается от тегов, адрес картинки принимается только `https`.
- Лимиты: 30 разборов ссылок и картинок в минуту, 5 таблиц в минуту на пользователя. Гостям без входа эти функции недоступны.
- Магазины видят запросы с адресов Cloudflare, а не пользователей; cookies и заголовки авторизации не передаются.

Остаточный риск: Workers не даёт контролировать DNS-разрешение, поэтому публичное имя, указывающее на внутренний адрес, отсекается только тем, что у Workers нет доступа к частным сетям. Не размещайте API в окружении с доступом к внутренней сети без отдельного egress-фильтра.

## Импорт таблиц

Файлы `.xlsx` и `.csv` разбираются в браузере (`src/import/`) без исполнения формул и макросов: читаются только значения, гиперссылки, цвета заливки, адреса из формул `IMAGE`/`HYPERLINK` и картинки. Скрытые листы пропускаются. Картинки по ссылкам из формул `IMAGE` в предпросмотре грузятся напрямую с указанного сайта (`referrerpolicy=no-referrer`), а при сохранении — через API по правилам выше.

## Ограничения и эксплуатация

- CORS допускает только `APP_ORIGIN`, но не заменяет авторизацию. Cookies не используются. В мини-приложении `initData` остаётся в памяти Telegram WebView; на сайте ключ входа хранится в `localStorage` (см. «Вход на сайте»).
- API-ответы: `Cache-Control: no-store, private`. Никаких ETag по состоянию брони.
- Внешние ссылки — только HTTPS, без credentials. Серверное скачивание по URL ограничено правилами из раздела «Загрузка данных с других сайтов». SVG/data HTML не принимаются для фото. Загруженное фото превращается в bitmap WebP на клиенте.
- React экранирует тексты; `dangerouslySetInnerHTML` отсутствует. CSP ограничивает скрипты собственным доменом и официальным Telegram SDK.
- Rate limit: 240 запросов/мин на Telegram-пользователя, 120 на IP для анонимных гостей, 10 заявок в друзья/мин (защита от перебора ников), 10 открытий приглашений/мин, 5 новых гостевых ссылок и 5 приглашений/мин. Это защита приложения; массовый DoS может исчерпать Free-квоты. CORS не блокирует прямые запросы злоумышленника.
- SQL-ошибки и заголовки не логируются; Workers Observability отключена. Не включайте логирование auth/URL/token без редактирования чувствительных полей.
- Резервные копии содержат профили, дружбы, желания и брони. Хранить локально, не в публичном GitHub.
- После ротации токена бота обновите Cloudflare Secret `BOT_TOKEN`; старые `initData` перестанут проходить проверку.
- Закрывайте и открывайте Mini App при истечении часа. Не ослабляйте срок проверки ради удобства.

Проверки выполняются командой `pnpm test`. Перед приглашением близких выполните ручную приёмку в конце DEPLOY.md с двумя настоящими Telegram-аккаунтами.
