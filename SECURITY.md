# Модель доступа и безопасность

## Что защищается

Каждый API-запрос проверяет Telegram HMAC и `auth_date` (не более часа, с допуском 30 секунд в будущее). Клиент не передаёт доверенный user ID. Переданные поля `owner_id`/`user_id` не участвуют в выборе владельца подарка. Нет dev-пароля или серверного демо-режима.

Свои желания доступны владельцу; чужие — только при общей семье или активной гостевой ссылке на конкретного владельца. Фотографии защищены теми же правилами. Изменение/удаление подарка — только владельцем. При бронировании доступ проверяется повторно в атомарной SQL-команде. Все параметры SQL связаны через `bind`.

## Секретные брони

Для владельца и анонимного читателя SQL-запрос списка не обращается к `reservations`. Сериализатор не добавляет полей статуса, личности дарителя, времени или счётчика. Сортировка не зависит от брони. Редактирование и удаление собственного подарка имеет одинаковый результат с бронью и без неё. Владелец не может вызывать операции над собственной бронью; они отклоняются до обращения к таблице броней.

Другой подтверждённый читатель видит только `available`, `reserved` или `mine`. Имя и Telegram ID дарителя не возвращаются. У гостя без входа статусы отсутствуют. Для бронирования гость открывает ссылку в Telegram; вступать в семью не требуется. Свою бронь можно отменить после отзыва гостевого доступа/выхода из семьи. Отзыв ссылки не отменяет уже сделанные брони.

**Граница гарантии:** сервер не раскрывает бронь подтверждённому владельцу и анонимному пользователю. Невозможно определить, что владелец создал второй Telegram-аккаунт, получил чужой аккаунт или попросил родственника показать экран. Не давайте владельцу независимую гостевую идентичность с доступом к статусам. Администратор Cloudflare с прямым доступом к базе может видеть брони: это отдельная доверенная роль.

## Гостевые ссылки

32 криптографически случайных байта, base64url. В D1 хранится только SHA-256 токена. Срок 30 дней, новая ссылка отзывает прежние. Сырой токен возвращается только при создании. Обычный браузер хранит его в URL fragment, API получает в `X-Guest-Token`. Не добавляйте аналитику, error tracking, service worker cache, access logs или сторонние виджеты, которые собирают URL или заголовки. Telegram-ссылка содержит токен в startapp; это секрет доступа, отправляйте её только адресатам списка.

## Ограничения и эксплуатация

- CORS допускает только `APP_ORIGIN`, но не заменяет авторизацию. Cookies и sessionStorage/localStorage для авторизации не используются. `initData` остаётся в памяти Telegram WebView.
- API-ответы: `Cache-Control: no-store, private`. Никаких ETag по состоянию брони.
- Внешние ссылки — только HTTPS, без credentials. Нет серверного скачивания по URL (SSRF). SVG/data HTML не принимаются для фото. Загруженное фото превращается в bitmap WebP на клиенте.
- React экранирует тексты; `dangerouslySetInnerHTML` отсутствует. CSP ограничивает скрипты собственным доменом и официальным Telegram SDK.
- Rate limit: 240 запросов/мин на Telegram-пользователя, 120 на IP для анонимных гостей, 5 попыток вступления/мин, 5 новых гостевых ссылок/мин. Это защита приложения; массовый DoS может исчерпать Free-квоты. CORS не блокирует прямые запросы злоумышленника.
- SQL-ошибки и заголовки не логируются; Workers Observability отключена. Не включайте логирование auth/URL/token без редактирования чувствительных полей.
- Резервные копии содержат данные семьи и брони. Хранить локально, не в публичном GitHub.
- После ротации токена бота обновите Cloudflare Secret `BOT_TOKEN`; старые `initData` перестанут проходить проверку.
- Закрывайте и открывайте Mini App при истечении часа. Не ослабляйте срок проверки ради удобства.

Проверки выполняются командой `pnpm test`. Перед приглашением семьи выполните ручную приёмку в конце DEPLOY.md с двумя настоящими Telegram-аккаунтами.
