# Автозаполнение по ссылкам: проверка и ограничения

Работает на существующем Worker, без дополнительных сервисов, подписок, секретов и миграций. Новое исправление подготовлено отдельным PR поверх main.

## Исправление фото на iPhone и Mac

Сбой воспроизведён в настоящем Safari на фото Amazon `B0C9TP6DD5`: файл успешно скачивался через API, но форма показывала «Фото слишком детальное». Причина — `canvas.toDataURL("image/webp")`: при отсутствии WebP-кодировщика браузер возвращает PNG, а изменение качества не уменьшает его размер. Поведение описано в [MDN](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toDataURL).

Теперь обработка проверяет фактический формат, пробует JPEG и при необходимости уменьшает размеры. Прозрачность перед JPEG заполняется белым. В API по-прежнему отправляется сама сжатая картинка, а не зависимая от магазина внешняя ссылка. Лимит 215 000 символов и проверка формата сохранены. Ошибка загрузки больше не скрывается за общей надписью: форма показывает конкретную причину.

После исправления в Safari проверены реальные фото Amazon и Wildberries: оба отображаются. Для этой проверки использованы настоящая форма, локальный Worker и отдельная тестовая D1 с вымышленным токеном; пользовательские данные Telegram не использовались. Это проверка браузерного этапа, а не публикация новой версии.

## Реальные запросы из Cloudflare, 25 октября 2026

Проверено в официальном Cloudflare Workers Playground кодом из репозитория. Полный обработчик `/api/fetch/image` запускался с вымышленной авторизацией и тестовой заглушкой D1. Секреты и настоящая база в Playground не передавались.

| Ссылка | Фактический результат |
| --- | --- |
| Amazon.es `/dp/B0C9TP6DD5` | Название KnitPro, 52,87 EUR, основное фото. API фото: HTTP 200, JPEG, 101 543 байта. |
| Wildberries `/catalog/212550828/detail.aspx?size=339839029` | Название «Пехорка…», фото: HTTP 200, WebP, 120 544 байта. Card v4 вернул `totalQuantity: 0`, `stocks: []`, без цены. Придумывать цену или брать её у другого товара нельзя. |
| Ozon `/search/?product_id=2402035826&…` → `/product/2402035826/` | Данные товара не получены. Запасной composer-запрос теперь выполняется и при сетевой ошибке основной страницы; это не гарантия доступа к Ozon. |
| AliExpress.ru `/item/1005002333850679.html?sku_id=12000031578956806` | HTTP 200, но защитная страница размером 2061 символ, без данных товара. Автозаполнение недоступно. |

WB использует в card v4 поле `optionId`, более старый ответ — `chrtId`. Поддержаны оба формата. Если магазин прямо сообщает нулевой остаток, интерфейс объясняет отсутствие цены. Отсутствующая цена сама по себе не считается отсутствием товара.

Ozon и AliExpress могут требовать интерактивную проверку или вход. При такой блокировке фото можно загрузить файлом/из буфера, название и цену ввести вручную. Платные прокси, CAPTCHA-сервисы и обход защиты не подключены. Наличие парсера не означает, что магазин разрешает автоматическое чтение из Cloudflare.

## Остальное поведение

- Amazon: реклама удаляется из URL, сохраняется ASIN; цена берётся из основной области, исключены зачёркнутые цены и рекомендации.
- Ozon: `product_id` из поиска превращается в ссылку на товар. Цена по карте Ozon не подменяет общую цену.
- Wildberries: выбранный `size` сохраняется. Неизвестному варианту не присваивается цена другого размера.
- AliExpress: `sku_id` сохраняется, рекламный `spm` удаляется; доступную цену и вариант нужно проверить.
- Ответы, пришедшие позже ручного изменения поля или смены ссылки, не перезаписывают данные. Во время загрузки нельзя сохранить незавершённую форму.

Цены зависят от региона, времени, варианта и скидок. Обновление не делает мониторинг цен: автозаполнение выполняется при добавлении желания.
