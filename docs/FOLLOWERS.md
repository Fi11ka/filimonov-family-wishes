# Друзья с открытым и закрытым вишлистом

План перехода от взаимной дружбы с обязательным одобрением к односторонним связям с приватностью. Составлен 26 октября 2026 года. Первый этап сделан: сначала как подписки в духе Инстаграма, 27 октября интерфейс снова стал одним списком «Друзья» — два списка «Подписки» и «Подписчики» путали. Мероприятия и совместные подарки пока работают по-старому, только «свои люди» вместо друзей.

## Решения

| Вопрос | Решение |
| --- | --- |
| Профиль нового пользователя | Спрашиваем в окне «Добро пожаловать». По умолчанию закрытый |
| Нынешние профили | Остаются закрытыми |
| Минимальная карточка закрытого профиля | Имя, фото, @ник, число желаний |
| Кто видит, с кем человек дружит | Только сам человек |
| Старые ссылки «Поделиться» (`s_…`) и приглашения в друзья (`f_…`) | Ведут на профиль и доступа больше не дают |
| Гостевая ссылка «Для близких без регистрации» | Остаётся: это секретная ссылка владельца, её можно отозвать |
| Приглашения по @нику | Убираем везде: человек, который не заходил в приложение, их не увидит |
| Лимит активных броней | 5 у одного получателя на одного дарителя |
| Напоминания о дне рождения | Только тем, кто включил уведомления об этом человеке (колокольчик) |
| Кто попадает в мои друзья | Только те, кого я добавила сама. Кто добавил меня, виден отдельно, в «Добавили вас» |
| Одобрение запроса | По умолчанию добавляет человека в ответ (галочка над запросами) |
| Кого звать в совместный подарок | Своих людей галочками, остальных по ссылке на сбор |

## Модель данных

- `users.is_private` — 1 закрытый, 0 открытый. Нынешним профилям ставим 1.
- `follows(follower_id, target_id, status, created_at, approved_at)`, где `status` — `pending` или `approved`. Запись «follower добавил target в друзья» односторонняя: моё одобрение открывает человеку мой вишлист, но не мне его. Мне его откроет «Добавить в ответ».
- `subscriptions` остаётся как есть: это колокольчик «Уведомления об обновлениях». Он работает только при доступе к вишлисту.
- `friendships` и `friend_invites` после миграции больше не читаются. Таблицы удалим отдельной миграцией, когда переход устоится.

Миграция:

- каждая подтверждённая дружба → две одобренные записи (A → Б и Б → А);
- ожидающая заявка в друзья → запрос от того, кто её отправил;
- колокольчики сохраняются.

## Доступ к вишлисту

Вишлист, «о себе» и праздники видит:

1. сам владелец;
2. любой, если профиль открытый;
3. друг, которого владелец одобрил;
4. обладатель гостевой ссылки владельца (без регистрации, бронь по имени);
5. гость мероприятия, подтвердивший участие, — только вишлист хозяина праздника и только до следующего дня после праздника;
6. участник «Праздника для всех» — вишлист другого участника, если тот сам включил «Показать мой вишлист участникам».

Остальные видят минимальную карточку и кнопку «Добавить в друзья» (у закрытого вишлиста это запрос).

Отдельно от вишлиста: приглашённый в совместный подарок видит только карточку этого подарка и сведения о сборе.

Владелец по-прежнему никогда не узнаёт, кто бронирует его подарки.

## Ссылка на профиль

Одна постоянная ссылка `t.me/<бот>?startapp=p_<id>`, на сайте — `…/?p=<id>`. Сама по себе она доступа не даёт, поэтому её не нужно отзывать. В «Поделиться» две ссылки: на профиль и гостевая.

Найти человека можно только по его ссылке: поиска по нику нет.

## Профиль и друзья

- Профиль: «Кто видит мой вишлист» — «Все, у кого есть ссылка» или «Только те, кого я одобрю». Когда вишлист становится открытым, ожидающие запросы одобряются.
- «Добавить в друзья» открывает чужой вишлист сразу, если он открытый, или если этот человек уже добавил меня или попросил об этом. Иначе уходит запрос. Добавление того, кто ждёт моего одобрения, одобряет и его запрос.
- Вкладка «Друзья» — одна страница, блоки друг под другом:
  1. «Хотят в друзья» — только при закрытом вишлисте и запросах: «Одобрить» и «Отклонить», над ними галочка «При одобрении добавлять в друзья в ответ» (включена).
  2. Друзья — кого добавила я. Пометка «вы друг у друга», если он тоже меня добавил; колокольчик у имени, если включены уведомления. Счётчик «Друзей: N» считает только этот блок.
  3. «Ждут одобрения» — мои запросы к закрытым вишлистам, кнопка «Отменить запрос».
  4. «Добавили вас» — добавили меня, а я их нет: «Добавить в ответ», при закрытом вишлисте ещё «Закрыть доступ».
- «Убрать из друзей» при закрытом вишлисте и взаимной дружбе спрашивает галочкой «И закрыть этому человеку доступ к моему вишлисту» (включена). Без неё человек переходит в «Добавили вас». Он ни о чём не узнаёт.
- Бот: «X хочет добавить вас в друзья» с «Одобрить» (добавляет в ответ) / «Отклонить»; «X принимает вас в друзья»; «X добавляет вас в друзья» с кнопкой «Добавить в ответ» (для открытого вишлиста).

## Мероприятия

- Пригласить можно своих людей (друзей и тех, кто добавил меня) галочками или по ссылке на мероприятие `startapp=e_<токен>`. Ссылку можно заменить.
- Приглашённый видит название, дату и описание, а также кнопки «Участвую» / «Не смогу» в боте и в приложении.
- После «Участвую» гость получает доступ к вишлисту хозяина (пункт 5 выше). Дружбой это не становится.
- В «Празднике для всех» при «Участвую» есть галочка «Показать мой вишлист участникам», по умолчанию выключена.
- Хозяин видит всех приглашённых и их ответы. Гости видят только подтвердивших участие.
- Имена бронирующих видны только среди подтвердивших участие, как сейчас в «Празднике героя».
- Миграция: гости, которые сейчас дружат с хозяином, считаются подтвердившими. Добавленным по нику показываем приглашение заново.

## Совместный подарок

- Организатор зовёт своих людей галочками или по ссылке на сбор.
- Приглашённый видит карточку подарка, свою долю и кто уже участвует. Вишлист, «о себе» и праздники получателя ему не открываются.
- Непринятое приглашение не тратит лимит броней приглашённого.

## Лимит броней

- Не больше 5 активных броней у одного получателя на одного дарителя. Считаются свои брони и подарки, в сборе на которые даритель согласился участвовать.
- Проверка и запись — одной SQL-командой, поэтому несколько быстрых нажатий лимит не обойдут.
- После отмены брони место освобождается.
- Гостевые брони по имени лимит не считает: у гостя нет аккаунта.

## Порядок работы

Три отдельных PR, каждый можно выкладывать сам по себе.

1. **Друзья и приватность.** Модель данных и миграция, правила доступа, ссылка на профиль, вкладка «Друзья», переключатель в профиле и в приветствии, бот, напоминания. Мероприятия и совместные подарки в этом PR переводим на «своих людей» без изменения поведения. Сделано.
2. **Мероприятия.** Подтверждение участия, ссылка на мероприятие, без ников, «Показать мой вишлист участникам».
3. **Совместные подарки и лимит.** Ссылка на сбор, доступ только к карточке подарка, лимит 5 броней.

## Что заметят пользователи

- Нынешние друзья продолжают видеть вишлисты друг друга.
- Старые разосланные ссылки «Поделиться» перестают открывать вишлист закрытого профиля: посетитель увидит карточку и «Добавить в друзья». Тем, кто уже по ним заходил и дружит с владельцем, ничего не меняется.
- Напоминание о дне рождения придёт только тем, у кого включён колокольчик об этом человеке. Сейчас оно приходит всем друзьям, так что часть людей перестанет его получать.
