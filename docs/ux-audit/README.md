## Главное за минуту

Ядро продукта сделано добротно: тайные брони защищены на уровне API, есть архив вместо удаления, гостевая бронь по имени, автоподтягивание цены и фото. Основные UX-риски — не в логике, а в том, как она подана людям, которые не привыкли к сложным сервисам.

**Пять самых важных проблем (P0):**

1. **Мелкий текст и маленькие кнопки на телефоне.** В стилях 98 правил с размером шрифта 7–11 px; кнопка «Подарю!» — 9 px, описание на карточке — 10 px, кнопки на карточке 28–34 px в высоту. На телефоне карточки идут в две колонки шириной около 160 px. Для пожилых родственников это главный барьер.
2. **Гость не может увидеть и отменить свою бронь.** После брони карточка показывает «Уже выбрали» — так же, как чужие брони. Отменить можно только через владельца, то есть раскрыв сюрприз.
3. **Владелец видит, что ему подарят гости.** Экран «Управлять гостевыми бронями» показывает названия забронированных подарков и имена — прямо под плашкой «Вы не видите бронирования своих подарков».
4. **Даритель не узнаёт, что желание удалили или изменили.** При удалении бронь исчезает молча (каскад в БД), при редактировании даритель может купить не то.
5. **Тупик в форме редактирования.** Если фото желания не загрузилось, кнопка «Сохранить желание» блокируется навсегда.

**Принцип улучшений для MVP:** не добавлять новые сущности, а упростить существующие экраны — крупнее, меньше полей на первом шаге, одна понятная кнопка на каждый экран, явные подтверждения для отмены, нижняя навигация вместо бокового меню.
