# Сценарий 4. Отмена брони

Отмена есть у трёх ролей, и у каждой — свой путь.

| Кто отменяет | Путь сейчас | Подтверждение |
| --- | --- | --- |
| Друг / даритель по Telegram | Карточка «✓ Отменить бронь» **или** «Мои брони» → «Отменить бронь» | ❌ нет |
| Гость | Не может | — |
| Владелец (только гостевые брони) | «Мой вишлист» → «Управлять гостевыми бронями» → «Отменить бронь» | `window.confirm` |
| Неявно: владелец удалил желание | Бронь удаляется каскадом (`ON DELETE CASCADE`) | Дарителя никто не предупреждает |

## Предложение

```mermaid
flowchart TD
    subgraph FRIEND["Друг / гость со своей бронью"]
        A1["«Мои подарки» или карточка<br/>метка «Это дарите вы» → «Передумал»"] --> A2["Нижний лист: «Отменить выбор подарка<br/>«Наушники» для Маши?»<br/>«Да, отменить» / «Оставить»"]
        A2 -->|"Да"| A3["Тост «Подарок снова свободен»<br/>+ кнопка «Вернуть» 7 с"]
        A3 -->|"Вернуть"| A4["Повторная бронь,<br/>если ещё свободно"]
    end
    subgraph OWNER["Владелец: помощь гостю, не раскрывая сюрприз"]
        B1["Гость просит отменить"] --> B2["«Гостевые брони»: по умолчанию названия скрыты<br/>видно только «Мария · 1 подарок»"]
        B2 --> B3["Нажать «Показать подарки»<br/>с предупреждением «Вы увидите сюрприз»"]
        B3 --> B4["Отменить → своё окно подтверждения, не window.confirm"]
    end
    subgraph SIDE["Изменения владельцем"]
        C1["Удалил или изменил желание с бронью"] --> C2["В «Моих подарках» дарителя:<br/>«Желание удалено владельцем» / «Желание изменилось»<br/>с кнопкой «Понятно»"]
    end
```

**Ключевые изменения:**

- Единое подтверждение для отмены (свой компонент `Confirm`, не `window.confirm`).
- Undo в тосте на 7 секунд.
- Владелец по умолчанию видит только имена гостей и количество броней; названия — по явному действию.
- Не удалять бронь бесследно при удалении желания: оставить «след» для дарителя. Минимально — показывать в «Моих подарках» запись «Желание удалено владельцем» (потребует хранить название в брони или мягкое удаление).
